# metric-dictionary Specification

## Purpose
把「一个指标该怎么算」变成可被机器执行、可被引用、可被追溯的唯一来源，
消除跨部门口径二义性——让销售、运营、财务、采购说的是同一件事。

## Requirements

### Requirement: 指标定义唯一来源

系统 SHALL 用**随代码版本化的声明式指标文件**承载指标定义，每个指标 MUST 包含
名称、展示名、同义词、计算公式、所属数据集、粒度与负责人。

> 实现记录：立项时拟用 dbt 语义模型（MetricFlow）。实测 `dbt parse` 能加载，
> 但它的 metric 描述的是**聚合度量**（`sum(amount)`），与编排需要的**行级表达式**
> （`amount - cost`）不是一回事，且 `synonyms` / `owner` 非原生支持。
> 详见 `design.md` 的「实现记录」。

#### Scenario: 定义不完整时拒绝加载

- **GIVEN** 指标定义中存在缺少计算公式（或缺少所属数据集）的指标
- **WHEN** 系统加载指标字典
- **THEN** 系统 MUST 报出可定位到具体指标的错误
- **AND** MUST NOT 静默跳过该指标继续加载

#### Scenario: 指标引用的列必须存在

- **GIVEN** 某指标的计算公式引用了数据集中不存在的列
- **WHEN** 系统加载并校验指标字典
- **THEN** 系统 MUST 报错并指出是哪个指标、哪个列
- **AND** MUST NOT 等到编译或运行时才失败

#### Scenario: 锚定的数据集尚未上架

- **GIVEN** 某指标锚定的数据集在当前环境尚未注册
- **WHEN** 系统加载并校验指标字典
- **THEN** 该指标 MUST 被标记为不可用并给出提示
- **AND** MUST NOT 阻塞其余指标的加载
- **AND** 该指标被引用时 MUST 被拒绝，且错误信息 MUST 指向「数据集未上架」
  而不是「指标不存在」

#### Scenario: 同义词可被检索命中

- **GIVEN** 指标「毛利率」的同义词包含「毛利」
- **WHEN** 以「毛利」检索指标
- **THEN** 系统 MUST 返回「毛利率」

### Requirement: 指标口径可被编排引用

系统 SHALL 允许编排的派生字段算子以指标名称作为口径来源，
并在**编译期**展开为该指标定义的计算公式。

#### Scenario: 引用指标生成口径一致的表达式

- **GIVEN** 指标字典中已定义指标 `gross_margin`
- **WHEN** 流程中的派生字段算子引用该指标
- **THEN** 编译产物 MUST 使用该指标定义的计算公式
- **AND** 流程作者 MUST NOT 需要手写公式

#### Scenario: 引用不存在的指标被拒绝

- **WHEN** 流程引用了指标字典中不存在的指标
- **THEN** 系统 MUST 在保存或编译阶段拒绝
- **AND** 错误信息 MUST 列出可用的指标名

#### Scenario: 口径变更不需要改流程

- **GIVEN** 某流程引用了 `gross_margin`
- **WHEN** 指标定义中的计算公式被修改
- **THEN** 该流程下次编译的产物 MUST 使用新的公式
- **AND** MUST NOT 需要修改流程本身

#### Scenario: 历史版本不被追溯修改

- **GIVEN** 某流程的某个历史版本已经编译留档
- **WHEN** 指标定义随后被修改
- **THEN** 该历史版本的编译产物 MUST 保持原样

### Requirement: 问数前的指标对齐

系统 SHALL 在生成取数 SQL 前把相关指标的口径注入模型上下文，
使其不得自行猜测口径。

#### Scenario: 口径歧义时反问

- **GIVEN** 「销售额」在字典中同时存在支付口径与回款口径两个指标
- **WHEN** 用户提问「上月销售额」
- **THEN** 系统 MUST 向用户反问要采用哪个口径
- **AND** MUST NOT 默认选一个口径继续执行

#### Scenario: 明确口径后生成 SQL 与字典一致

- **GIVEN** 用户已明确选定某个口径
- **WHEN** 系统生成取数 SQL
- **THEN** 生成的表达式 MUST 与该指标定义的计算公式一致

### Requirement: 指标定义可追溯

系统 SHALL 让指标定义的变更随代码版本化，并记录每个指标的负责人。

#### Scenario: 变更走代码评审

- **WHEN** 某指标的计算公式被修改
- **THEN** 该修改 MUST 体现为一次可评审的代码变更
- **AND** 变更记录中 MUST 能看出改的是哪个指标

#### Scenario: 可查到负责人

- **WHEN** 查询某个指标的定义
- **THEN** 返回结果 MUST 包含该指标的负责人
