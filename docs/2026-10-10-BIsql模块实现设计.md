## 0. 总纲：先立规矩，再写模块

### 0.1 四条工程纪律（从现有代码里抄出来的，必须延续）

| 纪律 | 现有证据 | 对新模块的要求 |
|---|---|---|
| **取数只有一条路** | `app/assistant/tools.py` 注释明写"取数只有这一条路"，Web/REST/MCP/助手/Agent 五出口共用 | 编排、AI 算子、看板**全部**走 `run_scoped_sql` / `fetch_scoped_rows`，禁止自己拼 SELECT |
| **权限必须用 `resolve_grant`** | 仓库 MEMORY.md 明文："新增查询路径务必用 `resolve_grant`，不要直接用 `get_effective_grant`，否则管理员会 403" | 新代码一律 `resolve_grant` / `query_visible_datasets` |
| **标识符必须校验** | `access/scoped_query.py::check_ident`、`sync/spec.py::quote_ident` 两处正则 | 新模块的 SQL 拼接复用这两个函数，不新造 |
| **新增模型必须写 alembic 迁移** | `deploy/Dockerfile` CMD = `alembic upgrade head && uvicorn` | 每个新表配一条迁移，且 `alembic check` 必须无差异 |

### 0.2 命名与配置约定

- 表名：小写下划线，模块前缀（现有 `sync_tasks` / `agent_runs` / `monitor_tasks` → 新增 `data_flows` / `flow_runs` / `quality_checks` / `dashboards`）
- 配置：`app/settings.py` 里加字段，`env_prefix="BISQL_"`，snake_case，带默认值与中文注释
- 路由：`app/api/<模块>_api.py` 导出 `router`，在 `main.py::create_app()` 里 `include_router(router, prefix="/api/v1")`
- 调度 job id 前缀：已有 `sync_` / `monitor_` / `report_` / `dataset_discovery` / `erp_autosync` → 新增 `flow_`
- 包导出：新增模型必须在 `app/models/__init__.py` 里导出（现有文件靠一行 `__all__` + import 维护）
- 时间：模型统一 `_utcnow()` + `DateTime(timezone=True)`

## 1. 模块 M1：接入层（ingest）

### 职责
在**不动**现有 ERP 同步的前提下，新增非 ERP 源的接入能力。

### 现状与复用
- 保留：`app/sync/`（整库扫描 + 水位线 + 结构演进 + 重试告警），**一行不改**；
- 新增源（竞品库 / BOM / 物流账单 / HR / 生意参谋）走 `app/ingest/`，用 **dlt**。

```python
from app.sync.discovery import discover_datasets

def run_ingest(source_name: str, *, session_factory, pg_engine, schema: str = "ods") -> dict:
    import dlt

    pipeline = dlt.pipeline(
        pipeline_name=f"ingest_{source_name}",
        destination=dlt.destinations.postgres(credentials=_pg_dsn()),
        dataset_name=schema,
```

## 2. 模块 M2：编排层（flow）—— 本次核心

### 2.1 分层执行模型（关键，先想清楚再写）

```
画布（React Flow）
  → DSL（JSON，Pydantic 校验，= LLM structured output schema）
  → 编译（compile.py）
      ├─ SQL 节点  → dbt model（SQL）+ schema.yml（tests + 中文 description）
      └─ AI 节点   → Python 计算（app/ai/operators）
  → 编排（Dagster：AI asset → dbt asset，异构节点同一资产图）
  → 执行
      ├─ SQL：dbt build（目标 PG；预览用 DuckDB）
      └─ AI ：Python runner（结果物化成表，供 dbt JOIN）
  → 产物注册进 datasets（自动获得权限 + 四出口）
```

**为什么 AI 节点不能进 dbt**：dbt 只会写 SQL，调不了 LLM。所以 AI 节点由 Python 执行、**产出"键→值"映射表物化到 PG**，dbt model 里 JOIN 这张表。Dagster 的 asset 天然支持这种异构混合。

### 2.3 流程 DSL `app/flow/dsl.py`

**这一份 Pydantic 模型同时干三件事**：① 后端校验 ② 前端 JSON Schema（自动渲染配置表单）③ **LLM 结构化输出 schema**（NL→Pipeline 直接复用）。一份定义三处用，避免漂移。

```python
class PortSpec(BaseModel):
    name: str
    kind: Literal["table", "column", "value"]

class OperatorSpec(BaseModel):
    """算子元数据——由注册表在启动时生成，前端拿它渲染算子面板。"""
    type: str                     # clean.dedup
    category: str                 # 清洗
    title: str                    # 去重
    description: str
    inputs: list[PortSpec]
    params_model: type[BaseModel] # ★ params 的 Pydantic 模型 → JSON Schema

class FlowNode(BaseModel):
    id: str
    type: str
    params: dict
    position: dict[str, float] = {"x": 0, "y": 0}   # 仅为画布回显

class FlowEdge(BaseModel):
    source: str
    target: str

class FlowOutput(BaseModel):
    materialization: Literal["table", "view"] = "table"
    target_schema: Literal["dwd", "dws", "ads"] = "dwd"
    target_name: str
    register_dataset: bool = True
    # 产物权限：默认仅 owner；list[int] 表示额外授权给这些 user_id
    share_with: list[int] = []

class FlowDSL(BaseModel):
    name: str
    title: str
    description: str = ""
    nodes: list[FlowNode]
    edges: list[FlowEdge]
    output: FlowOutput

    @model_validator(mode="after")
    def _check_dag(self):
        """校验：无环、无孤立节点、有且仅有一个 sink、端口类型匹配。"""
        _assert_acyclic(self.edges)
        _assert_single_sink(self.nodes)
        return self
```

```python
class Operator(ABC):
    """每个算子 = 纯函数 + 参数模型。纯函数 → 可单测、可换引擎、可被 LLM 当工具调。"""

        """返回一段 SQL 片段（通常是 CTE）。SQL 类算子实现这个。"""
        ...

        """AI 类算子实现这个（产出一张表，供下游 JOIN）。"""
        raise NotImplementedError
```

```python
# app/flow/operators/registry.py
REGISTRY: dict[str, Operator] = {}

def register(op: Operator) -> Operator:
    REGISTRY[op.type] = op
    return op

def operator_catalog() -> list[dict]:
    """给前端的算子面板：一份带 JSON Schema 的清单。加算子不用改前端。"""
    return [{
        "type": o.type, "category": o.category, "title": o.title,
        "description": o.description,
        "paramsSchema": o.Params.model_json_schema(),
    } for o in REGISTRY.values()]
```

#### SQL 算子示例（去重 —— 用户点名的）

```python
# app/flow/operators/clean.py
from app.access.scoped_query import check_ident

class DedupParams(BaseModel):
    keys: list[str] = Field(description="判重主键列")
    keep: Literal["first", "last", "none"] = "last"
    order_by: str | None = Field(default=None, description="保留最新时按哪列排序")

@register
class Dedup(Operator):
    type = "clean.dedup"
    category = "清洗"
    title = "去重"
    description = "按主键或全字段去重，可保留最新一条"
    Params = DedupParams

    def compile_sql(self, ctx, node) -> str:
        p = DedupParams(**node.params)
        for c in p.keys:
            check_ident(c)                      # ★ 复用现有标识符校验
        keys = ", ".join(f'"{c}"' for c in p.keys)
        src = ctx.input_cte(node)               # 上游 CTE 名
        if p.keep == "none":
            return f'SELECT DISTINCT ON ({keys}) * FROM {src}'
        order = f'"{check_ident(p.order_by)}" DESC' if p.order_by else "NULL"
        direction = "ASC" if p.keep == "first" else "DESC"
        order = f'"{check_ident(p.order_by)}" {direction}' if p.order_by else "1"
        return (f'SELECT DISTINCT ON ({keys}) * FROM {src} ORDER BY {keys}, {order}')
```

> 沿用现有做法：**标识符原样拼接但先正则校验，值一律参数化**（见 `scoped_query.py` 的注释与实现）。

#### AI 算子示例

```python
# app/flow/operators/ai.py
class ClassifyParams(BaseModel):
    input_column: str
    labels: list[str]
    instructions: str = ""
    output_column: str = "ai_label"
    model: str = "deepseek-chat"          # 便宜模型；分类不需要 reasoner
    batch_size: int = 20

@register
class LlmClassify(Operator):
    type = "llm.classify"
    category = "AI"
    title = "LLM 分类打标"
    description = "把一列文本按给定标签分类（例：商品标题→类目）"
    Params = ClassifyParams

    def run_python(self, ctx, node, frames) -> "pa.Table":
        """AI 算子不产出 SQL，产出「键 → 标签」映射表，由 Dagster 物化后供 dbt JOIN。"""
        from app.ai.operators import run_llm_batch

        p = ClassifyParams(**node.params)
        df = frames[ctx.input_name(node)]              # 上游数据（Polars）
        # ★ 去重后调用：同一条文本只调一次 LLM（成本控制）
        uniq = df.select(p.input_column).unique()
        mapping = run_llm_batch(
            task="classify", values=uniq[p.input_column].to_list(),
            labels=p.labels, instructions=p.instructions,
            model=p.model, batch_size=p.batch_size,
            cache_key=f"{node.type}:{p.labels}:{p.instructions}",   # 结果缓存，同输入不重复调
        )
        return df.join(mapping, on=p.input_column, how="left")
```

### 2.5 编译 `app/flow/compile.py`

**最关键的一段：把 DSL 编译成 dbt model，且源必须经权限裁剪器。**

```python
def compile_flow(dsl: FlowDSL, *, session, owner) -> CompiledFlow:
    """DSL → dbt model SQL + schema.yml。owner 的有效授权决定源数据行权。"""
    order = _topological_order(dsl)     # 环已在 DSL 校验里挡掉

    ctes: list[str] = []
    for node in order:
        op = REGISTRY[node.type]
        if node.type == "source.dataset":
            # ★★★ 权限闸门：不直接 SELECT 源表，而是生成「带行权 WHERE 的子查询」
            ds = session.get(Dataset, node.params["dataset_id"])
            grant = resolve_grant(session, owner, ds.id)      # ★ 必须 resolve_grant
            if grant is None:
                raise FlowPermissionError(f"owner 对数据集 {ds.name} 无授权")
            scoped_sql, params = build_scoped_sql(ds, grant, {}, limit=10**9, offset=0)
            ctes.append(f'{_cte(node.id)} AS (\n  {_bind(scoped_sql, params)}\n)')
        else:
            ctes.append(f'{_cte(node.id)} AS (\n  {op.compile_sql(ctx, node)}\n)')

    final = f'SELECT * FROM {_cte(dsl.output_node_id)}'
    model_sql = (
        f"{{{{ config(materialized='{dsl.output.materialization}', "
        f"schema='{dsl.output.target_schema}', alias='{dsl.output.target_name}') }}}}\n"
        + "WITH " + ",\n".join(ctes) + "\n" + final + "\n"
    )
    return CompiledFlow(
        model_sql=model_sql,
        schema_yml=_generate_schema_yml(dsl),      # 把 quality.assert 节点转成 dbt tests
        selector=f"{dsl.output.target_schema}.{dsl.output.target_name}",
        input_datasets=[...],                       # 供血缘与权限继承
    )
```

**为什么把裁剪后的子查询内联成 CTE 而不直接用 `source()`**：dbt 的 source/ref 宏无法带 WHERE 条件，而权限必须体现在 SQL 里。代价是静态血缘要靠 `FlowRun` + Dagster 资产图补，收益是**编排不可能绕过权限**。

> 若后续希望 dbt 静态血缘更完整，可增加一个 `scoped_source` macro 版本（用 `--vars` 传行权），作为 V2 优化项。

### 2.6 执行 `app/flow/runner.py`

```python
def run_flow(session, flow: DataFlow, *, triggered_by: str, pg_engine, settings) -> FlowRun:
    version = _current_version(session, flow)
    dsl = FlowDSL(**version.dsl)
    owner = session.get(User, flow.owner_user_id)

    run = FlowRun(flow_id=flow.id, version=flow.current_version,
                  triggered_by=triggered_by, status="running")
    session.add(run); session.flush()

    try:
        compiled = compile_flow(dsl, session=session, owner=owner)
        run.grant_snapshot = _grant_snapshot(session, owner, compiled.input_datasets)   # ★ 审计
        _write_dbt_model(settings.dbt_project_dir, compiled)          # 落到 dbt/models/generated/
        result = _dbt_build(settings.dbt_project_dir, compiled.selector)  # dbt build（含 tests）
        _emit_openlineage(compiled, run)                               # 血缘
        run.status = "ok" if result.ok else "failed"
        run.rows_out = result.rows
        if result.ok and dsl.output.register_dataset:
            _register_output_dataset(session, flow, compiled)          # ★ 默认仅 owner 可见
    except FlowPermissionError as exc:
        run.status, run.error = "aborted", str(exc)
    finally:
        run.finished_at = _utcnow()
        session.add(run); session.commit()
    return run
```

**AI 节点怎么落**：`runner` 先用 Python 跑完所有 AI 节点（结果物化成 `ods._ai_cache_<node_id>` 或 `dwd._ai_<flow>_<node>`），再让 dbt JOIN 这些表。Dagster 的资产依赖会自动排好先后。

```python
def structured_call(prompt: str, schema: type[BaseModel], *, model: str | None = None,
                    retries: int = 2) -> BaseModel:
    """约束 LLM 输出为给定 Pydantic 模型；解析失败把错误喂回重试。"""
    for attempt in range(retries + 1):
        raw = chat(prompt + _schema_hint(schema), model=model or model_for("sql"))
        try:
            return schema.model_validate_json(extract_json(raw))
        except ValidationError as exc:
            prompt = f"{prompt}\n\n上次输出不合法：{exc}\n请严格按 JSON Schema 输出。"
    raise StructuredOutputError("LLM 连续返回非法结构")
```

### 7.3 混合检索 `app/ai/retrieval.py`

```python
def hybrid_search(query: str, *, table: str, top_k: int = 5, filters: dict | None = None,
                  user=None, session=None) -> list[dict]:
    """BM25 + 向量 + RRF 融合 + rerank —— RAG 的标准最优实践链。

    ★ 权限前置：候选集先用 query_visible_datasets + 行权过滤，再做检索。
    """
    bm25 = _pg_bm25(query, table, filters)          # PG tsvector / pg_trgm
    vec  = _pgvector_search(embed([query])[0], table, filters)
    fused = _rrf(bm25, vec)                          # Reciprocal Rank Fusion
    return _apply_rerank(query, fused)[:top_k]       # 用 bge-reranker 精排
```

```python
def run_llm_batch(*, task: str, values: list[str], cache_key: str, model: str,
                  batch_size: int = 20, **kwargs) -> "pa.Table":
    """批量调 LLM：去重 → 查缓存 → 分组并发 → 落缓存 → 返回映射表。

```

## 8. 模块 M8：权限与安全（贯穿全部模块）

### 三条硬规定（写进代码，写成测试）

| 规定 | 实现位置 | 测试 |
|---|---|---|
| **1. 编排读源必须过裁剪器** | `compile.py` 的 `source.dataset` 分支强制 `resolve_grant` + `build_scoped_sql`，无授权直接 `FlowPermissionError` | `test_flow_permission.py`：无授权 owner 跑 flow → aborted |
| **2. 产物继承来源行权** | `_register_output_dataset()` 把 input 的 `row_rules` 合并写进产物的 `dataset_grants`；产物默认**仅 owner 可见**（`share_with` 显式才放开） | 断言产物 grant 含 `warehouse='德清'` |
| **3. AI 算子的 prompt 不得含越权样例** | `run_llm_batch` 的输入只能来自**已裁剪**的 frame（因为上游 source 已裁剪，天然满足）；另加断言：prompt 组装前检查 frame 行数 ≤ 裁剪后行数 | 回归测试：有 `warehouse=德清` 的行权用户，prompt 里不得出现其他仓的值 |

## 11. 测试策略（延续现有 217 个用例的做法）

|---|---|---|
