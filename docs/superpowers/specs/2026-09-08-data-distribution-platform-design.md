# 数据分发中台设计文档

日期：2026-09-08
状态：待用户评审

## 1. 项目目标

构建一个部署在腾讯云 Linux 服务器上的数据分发中台，作为「ERP 系统」与「内部用户 / AI 智能体」之间的数据媒介：

- 定时从 ERP 数据库**增量拉取**销售订单、物流数据等业务数据；
- 通过统一的权限模型控制每个用户能访问的数据范围（行级）与字段（列级）；
- 以两种方式分发数据：**API 接口** 与 **数据文件（Excel/CSV）**；
- 提供 **MCP 接口**，让基于 AI 智能体的非开发人员用自然语言查询数据；
- 规模：100 人以内内部使用，单人（用户本人）开发与维护。

非目标：

- 不做实时（秒级）同步，定时增量即可；
- 不支持外部互联网第三方接入，仅公司内部员工；
- 不修改 ERP 系统，只读访问。

## 2. 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI | 数据工程主场；异步 API；单人迭代快 |
| 中台数据库 | PostgreSQL 16 | 贴源存储 + 元数据一体；JSONB 存配置；行级权限可用 SQL 表达 |
| 调度 | APScheduler | 进程内定时任务，满足单机规模，无需额外中间件 |
| ERP 访问 | SQLAlchemy + 对应数据库驱动（按 ERP 实际类型确定） | 只读连接，独立连接池 |
| 前端 | React + Ant Design (Vite) | 管理后台组件齐全，界面清晰美观 |
| AI 接入 | MCP Python SDK | 智能体自然语言查数的官方标准接口 |
| 部署 | Docker Compose + Nginx | 腾讯云 Linux 一键部署，HTTPS 终止在 Nginx |
| 迁移 | Alembic | 数据库结构版本化管理 |

## 3. 整体架构

```
┌─────────────┐     ┌──────────────────────────────────────────┐
│  ERP 数据库  │◄────│  ① 同步引擎（定时增量拉取）               │
└─────────────┘     └───────────────┬──────────────────────────┘
                                    ▼
                    ┌───────────────────────────────┐
                    │  ② 中台数据库 PostgreSQL       │
                    │  (ods 贴源层 + 权限元数据)      │
                    └──────┬──────────────┬─────────┘
                           ▼              ▼
              ┌────────────────┐   ┌──────────────────────┐
              │ ③ API 网关      │   │ ④ 文件分发服务         │
              │ (鉴权/限流/审计) │   │ (Excel/CSV 导出/定时)  │
              └───┬────────┬───┘   └──────────┬───────────┘
                  ▼        ▼                  ▼
           ┌─────────┐ ┌─────────┐    ┌──────────────┐
           │ 系统 API │ │MCP 接口 │    │ Web 界面下载  │
           │ (内部系统)│ │(AI智能体)│    │              │
           └─────────┘ └─────────┘    └──────────────┘
```

数据单向流动：ERP → 中台 → 消费端。中台永不向 ERP 写入。

## 4. 模块设计

### 4.1 同步引擎（sync）

- 任务配置存于元数据表：源表、目标数据集、增量字段（`update_time` 类）、主键、同步周期（cron）、启用状态；
- 每次同步维护**水位线**（上次成功拉取到的增量字段最大值），拉取 `> 水位线` 的数据，采用 upsert 写入 ods 层，并记录 `synced_at`；
- **增量策略回退**：源表没有可靠增量字段时，退化为全量拉取 + 主键/内容哈希比对，只写差异行；
- 同步历史表记录每次运行的开始/结束时间、拉取行数、写入行数、错误信息；失败自动重试（指数退避），连续失败触发告警（邮件/企业微信 webhook）；
- ERP 侧使用只读账号，查询加超时与行数上限保护，避免拖垮 ERP。

### 4.2 数据集与权限元数据（catalog）

核心表（示意）：

- `datasets`：注册的数据集（对应一张 ods 表），含名称、描述、主键、可用字段清单；
- `users` / `roles`：用户与角色（管理员、普通用户）；
- `dataset_grants`：角色 ↔ 数据集授权，含**行级过滤规则**（JSON 表达：`{field: region, op: eq, value: 华东}`，可组合 AND/OR）与**字段白名单**（可访问列清单）；
- `api_keys`：Key 哈希、所属用户、过期时间、启用状态、限流配额；
- `audit_logs`：调用审计（主体、时间、数据集、过滤后 SQL 摘要、返回行数、耗时、来源渠道 api/mcp/web）。

行级规则在管理界面可视化配置；所有渠道（API / MCP / Web / 文件导出）最终都经过同一个**权限裁剪查询构造器**，保证口径一致。

### 4.3 API 网关（gateway）

- 路由：`GET /api/v1/datasets/{dataset}/rows`，支持分页、字段选择、简单过滤参数；
- 鉴权：API Key + 请求签名（Key + 时间戳 + HMAC），防重放；Key 可停用、设过期；
- 限流：按 Key 每分钟/每日配额；
- 响应：只返回该主体有权限的字段；行级规则注入 SQL WHERE；
- 全部请求写审计日志。

### 4.4 文件分发（export）

- 在线导出：Web 端按当前权限即时生成 Excel/CSV 下载；
- 定时报表：配置「每日 08:00 生成昨日订单 → 存服务器 → 用户端下载列表」，导出文件按权限生成、带水印（可选）、留存期可配置（默认 30 天自动清理）。

### 4.5 MCP 接口（mcp）

- 对外暴露 MCP 工具：`list_datasets`（只列出有权限的数据集）、`query_dataset(dataset, filters, fields, limit)`、`describe_dataset(dataset)`（字段与枚举说明）；
- MCP 会话绑定用户身份，查询走与 API 相同的权限裁剪器与审计；
- 供 Dify / Coze / 自建智能体作为工具接入，非开发人员用自然语言查数。

### 4.6 Web 界面（frontend）

管理员端：

- 数据源与同步任务管理（启停、cron、水位线、手动触发）；
- 同步监控看板（成功率、延迟、失败重试、告警记录）；
- 用户/角色管理、数据集授权（点选式行级规则与字段白名单）；
- API Key 管理、审计日志检索。

普通用户端：

- 数据集浏览（仅显示有权限的数据集）、在线查询表格（筛选、分页）；
- 一键导出 Excel/CSV；
- 我的 API Key（创建/停用）、我的调用记录、我的定时报表下载。

## 5. 数据流示例

以「华东区销售查销售订单」为例：

1. 同步引擎每 15 分钟从 ERP `sales_order` 增量拉取 `update_time > 水位线` 的行，upsert 到 `ods.sales_order`；
2. 用户通过 API Key 请求 `/api/v1/datasets/sales_order/rows`；
3. 网关校验 Key → 找到用户角色 → 取 `dataset_grants` 得到行级规则 `region = 华东` 与字段白名单（不含成本价）；
4. 构造 SQL：`SELECT 白名单字段 FROM ods.sales_order WHERE region = '华东' AND 用户过滤参数`；
5. 返回 JSON，写审计日志。

## 6. 错误处理

- 同步失败：重试 + 告警 + 监控看板红点，水位线只在成功后推进（失败不丢数据）；
- ERP 不可达：连接超时快速失败，不影响中台对外服务（对外读的是 ods 层）；
- 权限与数据不一致：字段白名单变更后，已缓存响应按数据集版本号失效；
- 导出大表：异步任务 + 进度提示 + 下载中心，避免请求超时。

## 7. 测试策略

- 单元测试：权限裁剪查询构造器（行级规则组合、字段白名单）为重点覆盖对象；
- 集成测试：使用 Docker 起临时 PostgreSQL，验证 upsert、水位线推进、全量比对回退；
- API 测试：pytest + httpx 对鉴权、限流、审计做契约测试；
- MCP 测试：对三个工具的权限边界做端到端断言（无权限数据集不可见）。

## 8. 部署

- 腾讯云 Linux，Docker Compose 编排：`nginx` / `api` / `worker(调度)` / `postgres`；
- HTTPS 证书（腾讯云免费证书）挂在 Nginx；
- 数据库与 ERP 连接信息走环境变量/.env（不入库不入 git）；
- 每日 PostgreSQL 逻辑备份到本机 + 腾讯云 COS（可选）。

## 9. 分期实施计划

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| P1 | 项目骨架 + 同步引擎 + ods 层 + 同步监控 API | 指定 ERP 表按时进中台，失败有重试告警 |
| P2 | 权限元数据 + API 网关 + Key 管理 | 能发 Key、行级/字段权限生效、审计可查 |
| P3 | Web 用户端 + 文件导出 + 定时报表 | 非开发人员自助查数与下载 |
| P4 | MCP 接口 + 智能体对接 | 智能体自然语言查数，权限口径一致 |
| P5 | 限流加固、备份、告警完善、使用文档 | 生产可用 |

## 10. 待实施期确认项

- 首批要分发的数据集清单与每个数据集的权限规则样例；
- 告警渠道（邮件 or 企业微信 webhook）。
