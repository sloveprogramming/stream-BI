# P4 MCP 接口与智能体对接实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans。Steps 使用 checkbox。

**Goal:** 通过 MCP（Model Context Protocol）把数据集以工具形式暴露给 AI 智能体（Dify/Coze 等），自然语言查数，权限口径与 API/Web 完全一致。

**Architecture:** FastMCP（mcp SDK v1，stateless HTTP + JSON 响应）挂载到 FastAPI 的 `/mcp` 路径；ASGI 中间件校验 `X-API-Key` 并把 Principal 写入 contextvar，工具函数从 contextvar 取身份，全部走 `build_scoped_sql` 裁剪并写审计（channel=mcp）。

**Tech Stack:** mcp>=1.10,<2（新增依赖）；其余沿用 P1-P3。

**Spec:** docs/superpowers/specs/2026-09-08-data-distribution-platform-design.md（§4.5 MCP 接口）

## Global Constraints

沿用 P1-P3 全部约束。新增：
- MCP 仅暴露三个工具：`list_datasets` / `describe_dataset` / `query_dataset`；
- MCP 通道鉴权只用 `X-API-Key`（智能体场景无浏览器跳转）；无效/停用一律 401；
- 所有工具调用写审计日志（channel=mcp, action=query/describe）。

## Tasks

### Task 1: MCP 工具核心逻辑（mcp_tools.py）
- Create: `backend/app/mcp_tools.py`；Test: `backend/tests/unit/test_mcp_tools.py`
- Produces:
  - `mcp_list_datasets(principal) -> list[dict]`
  - `mcp_describe_dataset(principal, name) -> dict`（字段+行级规则说明；无授权抛 ValueError）
  - `mcp_query_dataset(principal, name, filters, limit=50) -> dict`（走 build_scoped_sql + 审计 channel=mcp）
- TDD 四步 + commit `feat: MCP 工具核心逻辑（身份化裁剪查询）`

### Task 2: MCP HTTP 服务挂载与鉴权中间件
- Create: `backend/app/mcp_server.py`；Modify: `backend/app/main.py`；Test: `backend/tests/e2e/test_p4_mcp.py`
- Produces:
  - `mcp_app = FastMCP("bisql", stateless_http=True, json_response=True)`；三个 `@mcp_app.tool()` 包装 contextvar 身份；
  - `PRINCIPAL_CTX`（contextvars.ContextVar）；ASGI 中间件 `MCPAuthMiddleware`：path 以 `/mcp` 开头时校验 X-API-Key，成功 set contextvar，失败 401 JSON；
  - `create_app()` 中在 SPA catch-all 之前：`app.mount(mcp_app.settings.streamable_http_path, mcp_app.streamable_http_app())`。
- E2E：线程内起 uvicorn → `mcp.client.streamable_http.streamablehttp_client` + `ClientSession` → list_tools 断言三工具 → call_tool query_dataset 断言裁剪；无 Key → 401。
- TDD 四步 + commit `feat: MCP streamable-HTTP 服务挂载与 API Key 鉴权`
